## API

Same conventions as M2 (camelCase JSON, Unix seconds, bearer token, `{ error, code }`).

```
Squad   = { id, name, ownerId, members: [Member], openSessionId: string|null, muted, pet: { species: string|null, stage, xp } }
Member  = { id, handle, displayName, avatarCode, joinedAt }
Session = { id, squadId: string|null, hostId, status: "open"|"ended", createdAt }
Joined  = { session: Session, attributes: { sid, me, sq? }, contentState }   // ready for ActivityKit
```

Free: 1 squad, up to 4 members. Plus: 3 squads, up to 6 (SPEC.md §2). Member limits count the
squad's owner's plan as well as the joiner's, so a Plus owner's squad can hold 6.

## The room

One `Room` Durable Object per session. It holds every participant's timer and state, builds the
content-state (host first, at most 6 members; the squad pet; the latest cheer), bumps `v` on every
change, and:

- **Coalesces** changes for 2 seconds (an alarm), then pushes the latest state to every
  participant's Live Activity token with priority 10 for joins, finishes, early leaves and slips
  and 5 otherwise (SPEC.md §4.4); `stale-date` = latest running end + 5 minutes; `end` with
  `dismissal-date` = now + 30 minutes once the last member finishes or leaves.
- **Finishes timers itself**: an alarm at the next `ends_at` marks that member done.
- **Clears a cheer** about 10 seconds after it arrives (one priority-5 push).
- **Serves the WebSocket** (hibernation API) for the app's live view.
- **Counts pushes** per room and logs them when the room closes.
- Asserts every payload against the 3,584-byte budget and the whole APNs body against 4,096.

## App

- Home: a "Solo / <squad>" picker above Lock in when you're in a squad; Lock in with a squad joins
  its room (or opens it).
- Squads: list, create, invite (code, QR, link), join by code, squad detail (members' Locklings,
  mute, leave). Hitting a free limit opens the paywall (SPEC.md §2 paywall moment 2).
- Session screen in a squad: your Lockling large, squadmates in a row with their timers, live over
  the WebSocket; Cheer (a few emoji) on a squadmate.
- The engine starts the activity with the server's attributes and content-state, uploads every
  push token, applies WebSocket states locally too (Apple recommends both), and reconciles with
  `GET /sessions/:id` on foreground.
- Paywall moment 1: after the first completed squad session.

## As built (server)

Details the app relies on, settled while building the Worker (327 server tests):

- `Squad.ownerId` can be null; `members` are ordered by `joinedAt`; `muted` is the caller's own;
  `GET /squads` lists squads in the order the caller joined them.
- Squad invites are `FriendCode`-shaped; one current code per squad and inviter, renewed after 7
  days; codes stop working when their creator leaves. `POST /squads/join/:code` with a friend code
  answers 422 `friend_code`, so for a `/j/<code>` link the app tries `squads/join` first and falls
  back to `friends/redeem`.
- Member limit: 6 if the owner or the joiner has Plus, else 4; squad-count limit checked first.
- `minutes` is a whole number 1–240 (422 `minutes_invalid`). Custom lengths are a Plus feature in
  the app only.
- `Joined.contentState.v` starts at 1; `p` is in every squad room from M5 (an egg is `"<species>.0"`); `c` is present for
  10 seconds after a cheer.
- `GET /sessions/:id` → `{ session, contentState }`, with `contentState` null once an ended room
  has been cleaned up (24 hours after it ended).
- WebSocket `GET /sessions/:id/live` (bearer auth; 426 `upgrade_required` without an upgrade):
  messages `{ "type": "state", "status": "open"|"ended", "contentState": … }` on connect and right
  after every change; closes with 1000 after `ended`; `{"type":"ping"}` → `{"type":"pong"}`.
- Extra error fields: `limit` on 402, `sessionId` on 409 `already_in_session`, `retryAfter`
  (seconds) on 429. Other codes: 404 `session_not_found`, 409 `room_full` (a seventh person only
  replaces someone who left), 503 `try_again`, 422 `cheer_invalid` (`to` must be another member,
  `kind` 0–7), 403 `not_member` for anyone outside the room's squad.
- pause only while focusing (finishes you instead if your time is up); resume moves your end by
  the pause; end = done if your time is up, else left; slip = state 5, timer stopped, `slips` + 1.
- Joining again while running returns the same `Joined`; after finishing it starts a new timer in
  the same room.
- A member still running 8 hours after joining becomes left, so an abandoned pause can't hold a
  room open.
- Names in the activity: display name, else handle cut to 12, else "Lockling".
- `DELETE /auth/session` signs out (deletes the caller's token).
- Not yet: breaks (state 1), pet XP and hatching (M5), removing a member, a new block removing
  someone from a shared squad, renames reaching running activities, `apns-expiration`.

## As built (app)

Where the app differs from the interfaces above, settled while building it:

- `APIError.server` carries a fourth value, `details: APIErrorDetails` (`limit`, `sessionId`,
  `retryAfter`), rather than `plusLimit` alone.
- `SessionInfo.hostId` is `""` when the server sends null (a host who deleted their account).
- `start(minutes:)` is solo only; squads go through `startSquad(squadId:minutes:)`, which throws
  `SquadSessionError.sessionInProgress` while another session runs.
- `mode` stays `.squad` through `.finished`, so the finished screen knows it was a squad session.
- `squadProblem` says when a pause, resume or end didn't reach the server; the engine retries by
  reading the room again, and the session screen says "Can't reach your squad. Still trying."
- `slip()` (for M8) and `ownsActivity(id:)` (so launch clean-up leaves a squad activity the engine
  took up again) were added.
- A slip is gentle (docs/decisions/0009): slipped (state 5) is an active state, so the timer
  keeps running. The engine follows a slipped member's timer like a focusing one, `slip()` does
  nothing solo, the Live Activity keeps a slipped member's countdown ticking in pink (with Pause
  and End still offered), and a slipped member counts as in the session but not "locked in".
- `redeemInvite(code:squads:friends:)` is `@MainActor`, like the stores it uses.
- `SessionEngine.preview(phase:stats:avatar:mode:room:me:liveActivityProblem:)` builds an engine
  for snapshots.
