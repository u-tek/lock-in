# M6 — Viral surfaces

Status: **built**; waiting on the first `[snapshots: store]` run and the checks on a phone (see
"Next")

## Scope

From SPEC.md §1.7 and §6: share cards at session end, Home and Lock Screen widgets, a "Lock in"
interactive widget and Control Center control, onboarding that teaches the island and desk mode,
the two local reminders from §5.7, and App Store screenshots made from real screens.

Done when: every widget family renders in the Lab and on CI, the widget and the control start a
solo session with its Live Activity without opening the app, the share card renders at 9:16 and
1:1 and shares from the finished screen, and `[snapshots: store]` produces the App Store set.

## Widget data

The widget extension can't reach the network, so the app writes what widgets show to the App
Group (`Model.WidgetData`, JSON, a few hundred bytes) whenever it changes, then reloads timelines:

```swift
public struct WidgetData: Codable, Hashable, Sendable {
    public var avatar: String              // your Lockling's code
    public var todayMinutes: Int           // focused today, solo and squad
    public var soloStreak: Int             // your own days in a row
    public var squads: [Squad]             // up to 3
    public var session: Session?           // the one running now, so widgets can say "Locked in"
    public var updatedAt: Double           // Unix seconds

    public struct Squad: Codable, Hashable, Sendable, Identifiable {
        public var id: String
        public var name: String
        public var pet: String             // PetCode, e.g. "sprout.2"
        public var mood: Int
        public var progress: Double
        public var streak: Int
        public var countedToday: Bool
        public var lockedIn: Int           // in the squad's open room right now
    }
    public struct Session: Codable, Hashable, Sendable {
        public var endsAt: Double
        public var pausedAt: Double?
        public var squadName: String?
    }
}
```

## Widgets (in `Widgets/`)

| Widget | Families | Shows | Tap |
|---|---|---|---|
| Squad pet | small, medium, accessory circular and rectangular | the pet, its mood, the streak and the squad's name; signed out or squadless, your Lockling and your own streak | opens that squad |
| Lock in | small | your Lockling and a **Lock in** button (25 min); while a session runs, its countdown | the button starts a session without opening the app |
| Control Center: Lock in | control button | "Lock in" | starts a 25-minute solo session |

- Squad pet is configurable (`AppIntentConfiguration`) with a squad picker, the squads read from
  `WidgetData`; the default is your first squad.
- Starting from the widget or the control is a `LiveActivityIntent` (`StartSessionIntent` in the
  `LiveActivity` package, next to Pause/Resume/End), so iOS runs it in the app's process and
  ActivityKit lets it start the activity from the background. It goes through the same
  `SessionIntentBridge` (a new `.start(minutes:)` command).
- Countdowns are `Text(timerInterval:)`; nothing animates; accessory families are monochrome.

## Share cards (`ShareCards` module)

`ShareCardView(kind: .story | .square, card: ShareCard)` rendered with `ImageRenderer` at
1080×1920 and 1080×1080: the squad's Locklings (or yours, solo), the session's minutes, the streak,
the pet, and the invite code with "Lock in with me on Lockin". The finished screen gets a Share
button (`ShareLink` with the story image, the square as an alternative). No names of anyone but
you unless they're in the squad that just finished together.

## Reminders (`Notifications`, local)

- **Streak at risk**: once, at a time you pick (default 19:00), only if one of your squads hasn't
  counted today and you haven't finished a session today. Scheduled from `WidgetData` whenever it
  changes; cancelled when the day counts.
- **Weekly recap**: Monday 09:00 local, "Last week: 6 h 20 m locked in. Your squad came 2nd."
  from the last leaderboard the app saw.
- At most 2 a day across both (SPEC.md §5.7), and quiet hours apply.

## Onboarding

After the first finished session, two short tips with pictures, each shown once: "Lock your phone
— your squad's on the Lock Screen" and "Charging on its side? That's desk mode" (StandBy).

## App Store screenshots

`store.*` snapshot routes rendered on iPhone 16 Pro Max for `[snapshots: store]`: a headline over
a real screen at the store's 1320×2868. Five: the island with friends, the Lock Screen squad, desk
mode, the squad pet, solo + coins.

Snapshot routes: `widgets.pet`, `widgets.lockin`, `widgets.accessory`, `share.story`,

## As built

### Shipped: widgets, control and share cards

- **`Model.WidgetData`**, key for key as above, plus `WidgetDataStore`: `widget.json` in the App
  Group's `Widget` directory, written atomically with "until first unlock" protection so Lock Screen
  widgets can read it while the phone is locked. `asSeen(at:calendar:)` is what the data says on a
  later day than it was written: today's minutes 0, no squad counted, pets hungry, and a streak
  whose last counted day is before yesterday reads 0. Tests: `ModelTests/WidgetDataTests`.
- **`StartSessionIntent`** in `LiveActivity/SessionIntents.swift`: a `LiveActivityIntent` with a
  `minutes` parameter (default 25), discoverable in Shortcuts ("Lock in for 25 minutes"). It sends
  the new `SessionIntentBridge.Command.start(minutes:)` (the enum is now explicitly `Equatable`);
  `SessionEngine.handle(_:)` calls `start(minutes:)`, which starts a solo session only when nothing
  is running or paused (after a finish, or a timer that ran out, it starts a new one).
- **`WidgetViews`**, a new package module (Core, Model, DesignSystem, Creature, LiveActivity),
  linked by the widget extension and the app, for the same reason the Live Activity's views live
  in a package (docs/decisions/0001-live-activity-views-in-package.md): the snapshots draw what
  the extension draws. `SquadPetWidgetView` (small, medium, accessory circular and rectangular;
  the squad picked, else your first, else your Lockling and your streak), `LockInWidgetView`
  (idle with the `Button(intent: StartSessionIntent())`, running with `Text(timerInterval:)`,
  paused with the time left), `WidgetSurface` (the container background), `WidgetTimeline`
  (entries now, at the session's end and at midnight), `WidgetLink`, `WidgetKind` and
  `WidgetSamples`. Out of full colour (`widgetRenderingMode` other than `.fullColor`, passed in by
  the extension) creatures draw as outlines and nothing relies on colour. Tests:
  `WidgetViewsTests` (content, states, timeline dates, words, every family renders).
- **`Widgets/`**: `SquadPetWidget` (`AppIntentConfiguration` with `SquadPetConfiguration`, whose
  `SquadEntity`/`SquadQuery` list the squads in `WidgetData`; taps open `lockin://squad/<id>`),
  `LockInWidget` (small) and `LockInControl` (`ControlWidgetButton(action: StartSessionIntent())`),
  all in `LockinWidgetsBundle`. Timelines reload `.atEnd`.
- **App**: `WidgetDataWriter` (`App/Sources/WidgetSupport/`), owned by `LiveServices`, watches the
  engine (phase, stats, avatar, mode), the squads, the rooms' counts and the account with
  Combine, so a background launch for the widget's button writes too. It writes only when
  something a widget shows changed, then `WidgetCenter.shared.reloadAllTimelines()`. Signed out,
  no squads are written. `DeepLink.squad(id:)` (`lockin://squad/<id>`) picks the squad on Home
  through `NotificationInbox.pick`, the same path as a tap on an "is locking in" alert.
- **`ShareCards`**, a new package module: `ShareCard` (your Lockling and name; after a squad
  session the squad's name, the squadmates still in the room at the end, and its pet; minutes,
  your streak, your friend code), `ShareCardKind` (`.story` 1080×1920, `.square` 1080×1080),
  `ShareCardView` (white on the indigo tint, Locklings large, the number huge, the story's content
  inside the middle 1460 points clear of Instagram's bars), `ShareCardRenderer` (`ImageRenderer`
  at scale 1: `UIImage`, `Image`, PNG) and `ShareCardImage` (`Transferable`, a PNG rendered only
  when the share sheet asks). Tests: `ShareCardsTests` (words, lineup, pixel sizes, not blank,
  PNG).
- **Finished screen**: Share beside Done (`ShareCardButton`, a `ShareLink` with the story and
  itself as the preview; a long press offers the story or the square). `SessionCover` builds the
  card; there's none for a session under a minute.
- **Snapshot routes**: `widgets.pet`, `widgets.lockin`, `widgets.accessory` (the widget views in
  stand-in frames at the iPhone 16 Pro's sizes, `WidgetPreviewMetrics`: small 170, medium
  364×170, circular 76, rectangular 172×76), `share.story`, `share.square` (the renderer's images,
  scaled to fit) and `finished.share` (after a squad session).

### Shipped: reminders, onboarding tips and App Store screenshots

- **Reminders** (`Notifications`, pure): `ReminderPlanner.plan(data:settings:quietHours:log:recap:now:calendar:)`
  turns the widgets' `WidgetData` into the local notifications to schedule, soonest first.
  - *Streak at risk*, today and tomorrow at the time picked (default 19:00), each only when the
    data as it will read then (`asSeen(at:)`) says you've focused under the 20 minutes that count a
    day, no session is running, and a squad with a streak hasn't counted: "Library Goblins' 6-day
    streak needs you today 🔥" (the longest such streak; a one-day one is just "streak"). With no
    squad at risk, your own streak: "Your 3-day streak needs you today 🔥". Planning tomorrow's too
    means a day that counts moves the reminder to tomorrow, and a streak left uncounted has broken
    by then, so nothing nags about it.
  - *Weekly recap*, `recapSlot(after:)`: the next Monday 09:00 and the Monday-to-Monday week before
    it. "Last week: 6 h 20 m locked in." plus " You came 2nd in Library Goblins." when the app has
    seen that week's leaderboard for one of your squads (the first where you have minutes; the
    leaderboard's week is in the squad's time zone, so its middle has to fall in the local week).
    None for a week with no minutes. The minutes are this phone's: `SessionEngine.focusedMinutes(in:)`
    sums the sessions that ended in the week (`SessionEngine+Week.swift`).
  - *Quiet hours* (`deliveryMinute(_:quietHours:)`): a time inside them comes 15 minutes before they
    start, or, in the morning part of a window across midnight, when they end (23:00 → 21:45,
    06:00 → 07:00; the recap with quiet hours to 10:00 comes at 10:00).
  - *Two a day*: `ReminderLog` in the App Group's defaults (`LKReminderLog`) keeps one entry per
    reminder at its time. A local notification runs no code when it arrives, so it's kept at
    planning: what's still to come is replaced by each plan, and what's past counts as delivered
    for a week. A day already holding two gets no more; the streak reminder goes before the recap.
    `record(kind:at:)` is there for any other non-session notification.
  - `ReminderSettings` (`LKReminderSettings`, lenient JSON like `QuietHours`): streak on, 19:00,
    recap on. `QuietHours.contains(minute:)` is new.
  - Tests: `NotificationsTests/ReminderTests` (when and what the streak reminder says, sessions,
    quiet hours, the recap's slot, words and place, the daily limit, the log, settings) and
    `SessionEngineTests/WeekMinutesTests`.
- **App glue**: `ReminderScheduler` (`App/Sources/Notifications/Reminders.swift`), owned by the
  `WidgetDataWriter`, which hands it every state it builds (written or not, so the first of a
  launch counts too). It plans, and only when the plan changed replaces the pending requests whose
  ids start `lk.reminder.` (`UNCalendarNotificationTrigger`, one per kind a day,
  `lk.reminder.streak.2026-10-14`), and saves the log. Settings › Notifications gains a
  **Reminders** section: Streak reminder (and its Time), Weekly recap, a footer that says when quiet
  hours move the streak reminder; changing it, or quiet hours, plans again. A tap on a reminder just
  opens the app.
- **Onboarding tips** (`App/Sources/Onboarding/OnboardingTips.swift`): after a completed session,
  the tips not shown yet come up in a sheet (a height detent, then large) 1.4 s after the
  celebration: a two-page pager, "Lock your phone — your squad's on the Lock Screen" over the clock
  and the squad's Lock Screen card on the wallpaper, and "Charging on its side? That's desk mode"
  over a phone on its side in StandBy on a stand. Next, then Got it. Each tip is marked shown in the
  App Group's defaults (`LKOnboardingTipsShown`) as its page appears, so one swiped away unseen
  comes after the next session. The pictures are the LiveActivity module's views
  (`LockScreenPreview`, its StandBy layout) with the pitch's squad (`PitchActivity`: you, Ava,
  Noor and Kai in Library Goblins). Hooked onto the finished screen in `SessionCover` with
  `.onboardingTips(after:)`; never in snapshot mode. Routes `onboarding.tips` and
  `onboarding.tips.standby` (the second page).
- **App Store screenshots** (`App/Sources/Snapshot/StoreScreenshots.swift`): `store.1`…`store.5`,
  each a 440 × 956-point frame (1320 × 2868 on the iPhone 16 Pro Max): the headline in SF Pro
  Rounded Bold and a line under it, white on the tint deepening to purple, over a phone
  (`PhoneStandIn`, an iPhone 16 Pro drawn at 0.86 round a 402 × 874 screen, running off the
  bottom) or, for desk mode, a phone on its side. The system status bar is hidden; the phones draw

  1. "Your friends, in your Dynamic Island": the expanded island (`ExpandedIslandPreview`, all four

  2. "Lock in together": a Lock Screen at night: the clock, the Squad pet's circular and

  3. "Desk mode for study sessions": `StandByPhone` (the StandBy layout at full size) on a stand on

### Different from the plan

- The squads' **mood, streak and counted-today** now come from `GET /squads` (M5's `pet` and
  `streak`), read in `WidgetData.Squad.init(_:lockedIn:)`; the reminders rely on them.
- The share card's streak is **your own** (`FocusStats.streakDays`), for the same reason.
- The Lock in widget and the control always start **25 minutes**; the intent takes other lengths
  from Shortcuts only.
- The widget sizes in the snapshots come from Apple's size table, not a device: check them on a
  phone.
- The streak reminder also covers **your own streak** when no squad's is at risk (SPEC.md §5.7
  updated): solo mode is most people's first week.
- The recap's place is **yours within a squad** ("You came 2nd in Library Goblins"): the
  leaderboard ranks members, not squads. Its text is fixed when it's scheduled, so it holds the
  week as of the app's last change; a leaderboard is only known once the squad's page has been
  opened that week.
- The tips are a **sheet**, not an inline card: the finished screen's card slot already holds the
  friends or Plus card. There's a second route for the second page.
- The **screenshots' captions** are the ones above, not the listing's first draft (`store.island`
  … `store.plus`); the listing now matches. Headlines use SF Pro Rounded, which design/SYSTEM.md
  keeps out of the app: it's marketing, not UI.
- Not unit-tested in the app (no app test target): the tips' storage and the scheduler's glue.
  The rules they follow are in the package and tested there.
