## Risks

- **APNs from Workers.** APNs only speaks HTTP/2. Research says a *deployed* Worker reaches it
  (Cloudflare's edge upgrades to HTTP/2) but local `wrangler dev` never can (workerd#4841). If the
  deployed Worker can't, only the sender moves to a small Node `node:http2` service (SPEC.md §4.2).
  The spike decides: `docs/spikes/apns-worker.md`.
- **No Mac.** Every Swift build runs on CI; a compile error costs a CI round trip. Keep pushes
  small and the module tests fast.
- **Signing on CI.** TestFlight upload uses automatic signing with an Admin-role App Store Connect
  API key. The export signs with a cloud-managed distribution certificate, but the archive step
  makes a new Apple Development certificate on every fresh runner, and reports say the second run
  can fail. CI can use a stored development certificate instead (optional secrets
  `LK_DEV_CERT_P12` and `LK_DEV_CERT_PASSWORD`): `docs/decisions/0003-ci-development-certificate.md`.
- **APNs key environment.** A Sandbox-only key fails every TestFlight push with
  `BadEnvironmentKeyIdInToken`: `docs/decisions/0002-apns-key-environment.md`.
- **Provider tokens per isolate.** Several isolates signing their own JWT may trip APNs'
  per-connection rule in M3: `docs/decisions/0004-shared-apns-provider-token.md`.
- **CI simulators.** The `macos-26` image ships iPhone 17-series and 16e simulators, not the
  iPhone 16 Pro and iPhone SE named in CLAUDE.md; `scripts/ensure-simulator.sh` creates them.
- **Family Controls approval** can take weeks and extensions lag the app; it gates M8 only, so
  request it now (`docs/apple-setup.md`).
